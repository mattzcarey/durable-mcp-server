# CLAUDE.md

Instructions for Claude Code when working in this repo. General repo info lives in README.md, not here.

## Repo layout

- `apps/demo-client` — React UI + Worker (Vite, agents SDK). Connects to remote MCP servers.
- `apps/task-server` — Worker-only MCP server API (`@modelcontextprotocol/server`).
- `packages/durable-mcp-server` — TypeScript library. Bootstrapped only; implementation comes later.
- `design/` — the project brief (`design/brief.md`, the requirements source of truth) and the portability design note. **Read the brief before starting related work.**
- `docs/` — finished documentation: how it works, the demo, testing. Keep it in sync with the code.

## How to code here

- pnpm workspaces + nx. Run `pnpm check` (lint, format check, typecheck, tests, build) before every commit; it must pass.
- oxlint + oxfmt only — never add eslint or prettier.
- Strict TypeScript. No non-null assertions (`!`) — use destructuring, `.at()`, optional chaining, or explicit guards instead.
- No `.js` extensions on relative imports in TypeScript files.
- Follow the Cloudflare `agents` SDK patterns; keep UI consistent with the existing Kumo + Tailwind aesthetic — copy it, don't restyle it.
- `env.d.ts` files are generated by `wrangler types` (`pnpm -r run types`) and are committed; regenerate them after changing any `wrangler.jsonc` bindings. `wrangler types` emits tabs — always run `pnpm format` after regenerating or `pnpm check` fails.

## Testing rules

- All engine/DO/package tests run in workerd via `@cloudflare/vitest-plugin` (the renamed workers pool) against **real** Durable Object SQLite. Never simulate DO storage with `node:sqlite` or fake storage classes — prod behaves differently. A Durable Object fixture is the way to test storage-adjacent logic.
- Never mock `fetch` (no `vi.spyOn(globalThis, "fetch")`, no stub transports). msw is the only HTTP mocking tool.
- Every flow gets tested at four layers:
  1. **Data** — SQLite state inside the Durable Object, asserted via `runInDurableObject`.
  2. **Control plane** — the DO RPC methods and engine machinery called directly.
  3. **HTTP** — the worker's fetch surface (JSON-RPC bodies, headers, status codes).
  4. **Integrations** — the full flow end to end through the vitest-pool-workers harness.
- Alarms are driven with `runDurableObjectAlarm` drain loops, never real or fake timers.

## Dependency policy (strict)

- Only use npm packages Matt has explicitly approved. Currently approved: `@modelcontextprotocol/server` (MCP SDK v2), `agents`, `vite`, `react`/`react-dom`, `vitest` (+ `@cloudflare/vitest-pool-workers`), `oxfmt`, `oxlint`, `wrangler`, `typescript`, `nx`, `zod`, `msw` (approved 2026-08-20 for testing workers individually). Also in use from the upstream examples the apps were adapted from: `@cloudflare/kumo`, `@cloudflare/vite-plugin`, `@phosphor-icons/react`, `tailwindcss`, `nanoid`. Anything else: **ask Matt first**, then add it to this list.
- When Matt shows an external implementation (a repo or file link), **vendor** it: take only the code we need into this repo and credit the source in the README. Never `npm install` it.
- Every RPC call to a Durable Object needs retries (DO networking is unreliable). Use the vendored retry helper (pattern from lambrospetrou/durable-utils `src/retries.ts`, credited in README) — never call a DO stub method bare.
- oxfmt ignores `design/` and `docs/` (human-authored markdown) — keep it that way.
